# Keep Digging! — Design

**One line:** a giant hole, one server-wide depth counter, everyone digging to the bottom together. Spend Robux for a spectacular dig or play for free; the crew unearths valuable finds on the way; the first time this server's hole hits the bottom, a huge reveal plays and the hole resets deeper.

**3-second read:** big hole + big number going down + "+N m" pops + someone's drill-ship roaring into the shaft.

## Pillars
1. **The dig is the show.** Every Robux dig is a short, escalating, filmable sequence (see `src/shared/DigSequences`). Metres are credited instantly; visuals never delay them.
2. **One shared goal per server.** The hole is per server (no cross-server counter). Lifetime contribution, Collection and unlocks persist on the profile.
3. **Free path is real.** Auto-Digger, dig stations, obbies, minigames, daily reward and shared finds all move the counter. A full free-only server reaches the bottom in about 3 hours.
4. **Trust.** No paid randomness, exact prices and effects on every item, a Recent Purchases panel, no pressure timers, the Roblox purchase prompt every time.

## Core loop
1. Spawn on the rim in the reference scene: hole, Server Depth sign under the gate logo, Top Diggers board (left), Most Valuable Finds board (right).
2. Tap **DIG** -> store -> buy a dig. The sequence plays at the hole for everyone; the buyer's camera follows the descent (tap to skip).
3. The counter counts up, the depth marker slides down the ladder gauge, finds crossed by the marker are unearthed for everyone.
4. Free path keeps it moving between purchases. The Crew (NPC miners) adds a tiny population-scaled trickle.
5. Bottom reached -> Revealing -> Resetting -> a new, deeper hole with a new find seed.

### Reading the time-to-bottom table
* The hard anchors in the brief interlock: Pebble Toss is +1 m for 5 R$; no purchase may exceed 25% of the target (2,500 m); metres per Robux must improve with tier; and a maxed free-only full server must take at least 60 minutes. Together they pin paid digs to 0.200-0.250 m per Robux. That means paid digs are the accelerator and the spectacle, not the main engine. The free path, multiplied by boosts (capped at x4), does the bulk.
* A lively 30-player server reaches the bottom in about 45 minutes. A moderate one takes about 75 minutes, and small servers take hours. Server Boost is the most efficient purchase for the server as a whole (x2 for everyone), which keeps spending positive-sum. See DECISIONS.md.

## Free path details
* **Auto-Digger bay:** every player gets a rim bay. Lv0 is a hand-cranked bucket; Lv1-Lv5 are visibly different machines. The passive trickle is credited every 6 s and shown as "+0.1 m" floaties flying into the hole.
* **Dig Energy:** one token bucket per player shared by all active sources (stations, obbies, minigames). It refills at 1.2 base m/min, up to 6 m. The HUD shows it, and overflow becomes Season XP. Swing timing is also rate-limited server-side, so autoclickers gain nothing.
* **Dig stations:** a ProximityPrompt enters station mode; hold the big button to swing. Every 4 counted swings fill a bucket (+0.1 m).
* **Obbies:** Beginner (green neon, 12 stages) and Pro (purple/blue neon with a red hazard tower, 16 stages). Checkpoints are tracked server-side, with a minimum completion time.
* **Minigames:** behind the blue portal. **Gem Rush**: collect gems in a crystal arena. **Cave-In**: dodge falling voxel boulders. 45 s rounds.
* **Daily reward:** a 7-day streak of metres, Shards and XP.
* **Shards:** earned only by playing. They buy the Wood plaque, basic hats, a basic trail and a basic title. They can never be bought with Robux.

## Finds (deterministic and public)
* 21 find types in the Catalog, each with a fixed depth band (deeper = more valuable) and a count per cycle (31 placements per cycle).
* At the start of each cycle the server picks a seed. `HoleMath.PlaceFinds(seed, target, finds)` fixes every placement's exact depth.
* Placements are public from that moment: glowing markers on the ladder gauge, glints in the walls, and the Find Map UI (depth, name, status, cycle seed).
* Robux only ever moves the marker by an exact, shown number of metres; nothing is rolled at purchase time.
* When the depth crosses a placement, everyone in the server receives the find and the digger whose metres crossed it is credited as Finder. First discovery of a type grants Shards; duplicates grant 25% (min 2).

## Bottom event
`HoleService` owns a state machine: **Digging -> Revealing -> Resetting -> Digging**. The transition to Revealing happens synchronously inside `AddMetres` (no yields between the check and the state change), guarded by a per-cycle flag. That is exactly once, even when many digs land in the same frame. Digs bought during the reveal are banked and credited when the next cycle begins. The reset sets:
* a new target (+10% of base per cycle, capped at 1.5x);
* a new seed;
* cleared this-hole contributions;
* "Hole Breaker" credit and title for contributors.

## Data architecture
* **Server-authoritative.** Clients only request (`Net` remotes, all rate-limited and validated in `RemoteGuard`).
* **HoleService** (server memory only): depth, cycle, target, seed, placements, pool, this-hole contributions, bank, state. It replicates at 8 Hz over an `UnreliableRemoteEvent` and sends discrete events reliably. The counter never goes backwards inside a cycle.
* **DataService**: one versioned profile per player in DataStore `KD_Profiles_v1`. It uses session locking (`UpdateAsync` lock with JobId and heartbeat, stale after 30 min), retries with backoff, autosave every 75 s, and a final save on leave and `BindToClose`.
* **Pending gifts**: DataStore `KD_PendingGifts_v1` keyed by recipient UserId, entries idempotent by PurchaseId.
* **Leaderboards**: OrderedDataStores `KD_AllTime_v1` and `KD_Season_v1_<id>`. Writes are throttled; reads are cached and refreshed on a throttle; they are display only.
* **No MemoryStoreService, no MessagingService** anywhere (enforced by a test).

### Catalog schema
See the header of `src/shared/Catalog.luau`: Id, Category, Tab, Section, Name, Price | ShardPrice, Ownership, Purchase, Priority, Giftable, Slot, Effect, Description, Tier, Season. Finds have Id, Name, Rarity, Value, BandLo/BandHi (fractions of target), Count. The store, receipt routing, equip system, analytics, Finds board and the SETUP.md product table are all generated from it.

### Receipt flow
`ProcessReceipt` is the only handler for Developer Products:
1. Route by ProductId through the Catalog. If the player isn't in the server or the profile isn't loaded, return NotProcessedYet.
2. If the PurchaseId is already in the ledger, re-confirm the save and return PurchaseGranted.
3. Take the player's single pending-prompt context (gift target, dedication).
4. Apply the grant: to the recipient's profile, or to the pending-gifts store if they left.
5. Record the PurchaseId and the Recent Purchases row.
6. Save with `UpdateAsync`, and only then return PurchaseGranted.

If a one-time item is already owned, the buyer gets the closest-value dig instead and it is logged. Studio test mode builds fake receipts (`TEST-<guid>`) and calls the same function.
